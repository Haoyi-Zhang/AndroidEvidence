# Paper source

This directory contains the single-column ACM review source, bibliography, generated count fragments, and native TikZ figures. The review uses `manuscript,screen,review`, as required by the ACM-supplied journal template for initial review. Fonts, margins, and page dimensions come from the unmodified class.

## Build from the complete project

First reproduce the sibling artifact so manuscript-facing count fragments are current:

```bash
cd ../artifact
PYTHONDONTWRITEBYTECODE=1 python scripts/reproduce.py --out /path/to/check-output
cd ../paper
PYTHONDONTWRITEBYTECODE=1 python build.py --results /path/to/check-output
```

Keep that output directory outside the artifact to preserve historical raw results.
On Windows, set `PYTHONUTF8=1` and `PYTHONDONTWRITEBYTECODE=1` in the invoking
shell and use `python -B`. Without `--results`, the build imports the retained
`artifact/results/tex/` fragments; that default does not establish their freshness.

The build requires `pdflatex`, `bibtex` or `bibtex8`, and `pdfinfo`. It:

- audits all citations and requires at least 55 unique cited works;
- requires byte-identical paper and artifact bibliography snapshots;
- imports deterministic TeX fragments generated by the artifact;
- requires `\documentclass[manuscript,screen,review]{acmart}`;
- rejects `nonacm`, manual geometry/font overrides, and negative vertical spacing; unassigned DOI/reference/copyright furniture is omitted;
- compiles without shell escape;
- fails on overfull boxes, undefined citations/references, undefined control sequences, or a review copy exceeding the local 39-page budget;
- writes only `build/main.pdf` as the PDF output, plus `build-evidence.json`, `bibliography-audit.json`, and `bibliography-warnings.txt`;
- binds the output PDF and final log to the active TeX inputs, bibliography and publisher template. Delivery gates reject a stale PDF even if it fits the page budget.

The current manuscript built by this directory's owned driver has 38 pages including references. The local 39-page budget is a project constraint, not a verified CSUR-specific submission limit or submission certification. The driver reports the actual count; it does not add filler to occupy unused space. Corpus and citation checks establish local consistency, not independent interpretation of all sources. POSIX child CPU/RSS diagnostics are reported only where the operating system provides them. A paper build needs page-image inspection before use.

`build-evidence.json` records the current five-command compiler run, final engine log, selected source and PDF bindings. Unavailable Windows child CPU/RSS measurements remain null. `visual-inspection.json` records 180-dpi full-page layout coverage through new page views and exact pixel-identical carry-forward evidence, with the page sets and reviewing roles stated explicitly; `pdffonts` confirmed all listed fonts embedded and no Type 3 font. No clipped text, overlapping table/figure or citation-layout issue was observed. This layout inspection is not independent peer review or fulltext certification. The artifact's `manuscript_snapshot/build/main.pdf`, actual final engine log and compiled bibliography are byte-identical mirrors for artifact-only use, not a second compilation. Each tree has one `build/main.pdf` output; `paper/main.pdf` is only a byte-identical convenience copy. These receipts bind this build only. Rebuild and reinspect after later source changes.
